# Hot-Cluster CI — kubevirt-ui/kubevirt-plugin Change Log

Scope: moving kubevirt-plugin E2E testing off Prow (new AWS cluster per run) onto a persistent
"hot cluster" on IBM Cloud, driven entirely by GitHub Actions with ARC self-hosted runners.

- Epic: [CNV-74261](https://redhat.atlassian.net/browse/CNV-74261) — _Enable upstream kubevirt-ui CI testing on high capacity cluster_ (reported by Matan Schatzman, assignee Gal Kremer, created 2025-12-02; status still `New`).
- Implementation ticket: [CNV-74265](https://redhat.atlassian.net/browse/CNV-74265) — _DEV: Connect performance cluster+upstream testing_ (assignee Scott Dickerson, Closed). Scott's POC draft PR #3713 was linked 2026-04-01; the story's merged PRs were #4100 (2026-06-23), #4099 (2026-06-30), and #4175 (2026-07-02, `resolve-console-image.sh` CONSOLE_IMAGE override); first build containing the fix: CNV v4.23.0.rhel9-4; moved to Testing 2026-07-07 and closed after Ron Lavi's prompt on 2026-07-14.
- Follow-up umbrella: [CNV-97362](https://redhat.atlassian.net/browse/CNV-97362) — _DEV: e2e cluster - deploy release branch/clean up_ (Testing). Jira-linked PRs: #4889 (merged 2026-10-14), #4932 (2026-10-20), #4933 (2026-10-21); further PRs up to #5069 reference it in commit trailers.
- Downstream consumer: [CNV-87983](https://redhat.atlassian.net/browse/CNV-87983) — _Move
  network & nmstate E2E tests from kubevirt-ui to upstream plugin repos_ — explicitly adopted
  the hot-cluster CI pattern from this repo's PR #3713 to run migrated tests in
  openshift/networking-console-plugin and openshift/nmstate-console-plugin (the OCPNETUI-56
  work covered in the sibling changelog).

> Note: neither repo in this study used Jenkins for plugin E2E — kubevirt-plugin ran on
> **Prow/openshift-ci** and networking-console-plugin on **Prow ci-operator** (see the
> advantages doc for the Jenkins comparison the request asks for).

## Resulting architecture (as of 2026-11-09, `origin/main`)

```text
Cluster lifecycle (IBM Cloud; classic ROKS | VPC ROKS (recommended) | IPI):
  ibmc-cluster-setup.yml / ibmc-cluster-teardown.yml / ibmc-cluster-auto-teardown.yml (cron 2h idle)

E2E (single source of truth, workflow_dispatch-only — never a direct PR trigger):
  hot-cluster-e2e.yml  → prepare → cluster-check (hot-cluster-check.yml)
                       → progress-check-running-tests → run-e2e-tests (hot-cluster-e2e-run.yml)
                       → verify-gating-tests (publishes required "Run Gating Tests" check)

PR entry points (thin gates that only dispatch):
  hot-cluster-e2e-pr-gate.yml (opened/synchronize/reopened), ok-to-test-gate.yml,
  retest-e2e.yml, retest-failed.yml, retest-stale-gating.yml, retest-on-pool-entry.yml,
  hot-cluster-e2e-cancel-on-close.yml

hot-cluster-e2e-run.yml:
  build-kubevirt-plugin-image (podman → quay.io) → run-gating-tests (runs-on: kubevirt-plugin-ci ARC label)
    ci-env-request → ci-env-controller → ci-test-stack → BRIDGE_BASE_ADDRESS → Playwright

Merge automation (Prow/Tide replacements):
  auto-merge.yml (Merge Gate + native GitHub auto-merge), pr_validation_commands.yml (/lgtm /approve /hold),
  pr_review_commands.yml, needs-rebase.yml, verify-merge-pool-labels.yml, pr_help_command.yml
```

Key properties: per-release clusters (`kubevirt-plugin-XY`) with version-specific ARC runner labels;
concurrency caps per cluster; required "Run Gating Tests" check blocks merges; Prow/Tide fully removed
("Prow/Tide are gone for this repo" — ci-scripts/README.md).
